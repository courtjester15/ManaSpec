# Populated vanilla / React table comparison — 29 October 2026

## Scope and evidence

Owner requested review and suggestions, not implementation. Compared the current vanilla runtime and generated React portable candidate using isolated copies of the same newly exported backup: 38 Positions, 16 Radar items, 65 transactions, 8 notes, 37 market observations. Browser localStorage was replaced inside private QA wrappers with a disposable in-memory Map; no original browser store or backup was changed. No trades, imports into real stores, refreshes, or plan edits were performed.

In-app browser reviewed Radar, Positions, Signals, Transactions and History at 1366×768 and 1920×1080. Initial exploration also used the default 1280px viewport. Private wrappers, measurements and screenshots remain under ignored `.tmp/table-review*`; they contain user data and must not be committed or deployed. This report deliberately omits holdings, note text and financial amounts.

The browser viewport override applies to the selected tab, not every tab. Final target-size comparisons therefore navigated one tab between both implementations. Text clipping was measured from cell overflow and DOM text ranges, then checked visually; nested controls can produce range false positives, so counts are diagnostic, not acceptance assertions.

## Findings and proposed corrections

| Area | Observed difference | Recommended behavior |
| --- | --- | --- |
| Radar dates | React Added is 58px wide while locale dates include four-digit years. All 16 date cells overflowed in the populated sample. Vanilla Radar also retains long dates in a narrow column, so copying it blindly preserves a defect. | One compact table date formatter (`M/D/YY`) and a width sized for its longest supported result. Full date/time available on hover and in detail; underlying values and chronological sort unchanged. |
| Positions dates/hold/rarity | React uses four-digit-year dates in 64px, full rarity names in 52px and raw hold text in 62px. Vanilla uses compact dates, rarity initials and normalized month text. Long names such as Uncommon and hold strings clip in React even with more desktop width. | Shared display-only rarity `C/U/R/M/S` with full labels available; normalize visible holds such as `36 mo` and `6–12 mo` without rewriting saved strings. Compact dates. |
| Width allocation | React adds a fixed 58px Class column and 78px Detail column to Positions, where vanilla has no Class column and a 44px collector column. Extra metadata widths reduce name space on laptops. On wide screens React gives spare room to Asset while History Detail remains fixed at 220px and Notes at 72px. | Compact or conditionally expose asset class; use a narrow singles collector column and a product-appropriate width for sealed. Give History detail meaningful flexible width; don't direct all surplus into the name. Protect dates, signed money, and actions from clipping. |
| Cell padding / controls | React body cells use 6px horizontal padding; vanilla dense overrides use 4px. Radar's quantity stepper requires 64px before borders inside a 68px cell with 12px padding. It can be clipped even though the column looks spacious. | Shared compact per-column padding: roughly 4px for scan cells and 0–2px for embedded controls. Size from actual control bounds plus borders/padding. Preserve usable buttons and the existing 27px row rhythm. Avoid blanket padding removal or smaller fonts. |
| Signals | React Why is fixed at 112px versus vanilla's much wider reason region. Long reason pills clip, while Class, broad collector metadata and three actions consume space. | Give the reason more priority or use short, meaningful labels such as Missing Exit + Hold and Check Due, with full explanation accessible. Keep source navigation and actions distinct. Retain exact finish visibility. |
| Transactions | Full rarity labels clip in the same narrow columns used for initials in vanilla. React explicitly sorts the grid by Asset ascending, overriding an already date-descending input list. | Restore newest-first default using numeric timestamps; retain user sorting. Compact metadata and preserve full signed cash movement/balance values. |
| History | React formats full locale timestamps including seconds/AM-PM in 112px; all 25 displayed rows clipped. Notes displays note prose in 72px, while fixed Detail also clips summaries. React defaults to Asset ascending; vanilla defaults newest-first. | Compact date/time without seconds, full timestamp in detail/tooltip; newest-first default; note indicator/count instead of prose in the narrow Notes cell; flexible Detail and a deliberate way to read full event text. |
| Positions controls | Vanilla has rarity/type/color/price/print/plan filtering and a 25-row page-size control. React Positions currently has text + asset-class filters and no page-size prop, displaying the entire 38-row list. | Restore the useful existing filter/page-size contract through shared controls, including visible shown/total counts and Reset. Keep the asset-class filter. |
| Notes/history actions and finish | Vanilla Positions uses compact note/history affordances. React shows plain counts. React Positions also lacks an explicit visible finish marker in its normal columns; its detail-button label/tooltip has finish, but the primary cell only shows the name. | Reuse existing React Radar indicator buttons to jump directly to Notes/Price History. Show compact exact finish context for singles rather than requiring a tooltip or detail visit to distinguish rows. Preserve the intentional React row-body → Detail contract. |

## Important distinctions

- This is primarily a shared **formatting and width-allocation** problem, with padding contributing. Wider monitors do not repair fixed-width timestamp, rarity or note cells.
- Vanilla is a useful density/behavior reference, not a complete visual specification: its Radar dates also clip, and its compact money formatting differs from React's cents. Do not remove useful price precision merely to make React fit. Use a deliberate common display policy and adequate money widths; never change arithmetic.
- React History shows 126 events versus vanilla's 89 because its event builder also includes the 37 market observations. That count difference alone is not data duplication or loss.
- Some immediate post-navigation captures contained blank React-rendered cells; a later stable read showed populated names, values and controls with zero empty cell hosts and an empty console. These captures demonstrate deferred cell rendering, not confirmed persistent missing data. Future QA should wait for populated cells, not just the route heading, before screenshotting.
- The populated financial summary agreed between implementations before review. This was a presentation/behavior comparison, not a fresh valuation or data-integrity certification. Market observation labels and sparse legacy metadata should not be invented to improve visual completeness.

## Suggested implementation order

1. **Formatting and sizing:** shared compact dates/rarity/hold labels; correct stepper bounds; padding and money/date/action minimum widths. Fix History/Signals allocation. Verify longest observed content and a synthetic mixed sealed/foil/nonfoil fixture, since this backup has no sealed holdings.
2. **Behavior parity:** newest-first Transactions/History, Positions pagination/filter controls, note/history shortcuts and visible finish identity. Keep row actions isolated from Detail activation.
3. **Final populated QA:** both target viewports, stable populated cells, all five tables, sorting/filtering/reset/paging, keyboard editors and row controls. Export/import/reload only if persistence changes; presentation work should not change stored records.

Use one coherent React table parity Issue/PR, with no storage migration, framework replacement, analytics expansion or frontend promotion. No application code was changed during this review.
